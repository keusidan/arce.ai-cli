# 確かめたこと・確かめていないこと

## 確かめたこと（Linux x86_64、Rust 1.97、2026-11-08）
- `cargo test`：単体テスト 89 件（秘密の検査と伏せ字、権限とコマンドの分解、Markdown、Mermaid の読み取りと輪の検出、圧縮、分担の検査、SSE の道具の組み立て、セッションと取り消し、設定の信頼、フック、stdio の MCP サーバーとの往復など）と、結合テスト 9 件（`tests/e2e.rs`）がすべて通る。
- 結合テストは、偽の OpenAI 互換サーバーに対して実行ファイルを動かす：道具でファイルを書いて答える／非対話で書き込みが断られ、理由がモデルに返る／計画モードで書く道具が渡らない／テキスト形式の道具（`<think>`・`<tool_call>` が chunk の境目で切れる）／429 のあと最初の 1 字の前にフォールバック／同じ呼び出しの繰り返しで止まる／`-c` で履歴が続く／信頼していないプロジェクトの設定でモデルが別の送り先へ向かない／コーディングモードで 2 つの仕事が依存の順に動き、ファイルが書かれ、待った仕事に前の結果が渡る。
- `cargo clippy --all-targets` の警告 0、`cargo fmt` 済み。
- 疑似端末（`script`）で対話の承認カードを動かし、`y` で書き込み、`n 理由` でコマンドが止まり理由がモデルに渡るのを確かめた（`tests/e2e.rs` の `interactive_approval_yes_then_no`。Linux の `script` が要るので `cargo test -- --ignored` で動かす）。
- デモのモデルで、対話（スラッシュコマンド・`!コマンド`）と `-p`（text・json）を動かし、疑似端末で Markdown の表（全角の幅）が揃うのを見た。

## 確かめていないこと（未確認）
- **実際の提供元**（OpenAI・OpenRouter・DeepSeek・Gemini・Z.ai など）との通信。SSE の形・`usage` のキャッシュの数・思考の送り方・`prompt_cache_key` を断るときの文面は、arce.ai の実装と同じ前提で書いたが、この環境から本物の API には送っていない。
- **macOS と Windows**での動き（CI(Continuous Integration) に入れたが、この環境では動かしていない）。Windows ではコマンドを `cmd /C` で動かす。秘密のファイルの権限（0600）は Unix だけ。
- 実際の MCP サーバー（テストは sh で書いた小さなサーバー）。
- Web 検索（DuckDuckGo の即答 API・SearXNG）の実際の応答。
- 長い会話の自動の要約を、実際のモデルで（質と所要時間）。

## 既知の制限
- 全画面の TUI(Text User Interface) ではなく、行ごとの表示。Markdown は行が終わってから描く（長い段落は、改行まで出ない）。
- 画像の添付は無い（テキストだけ）。
- OS のサンドボックスは無い。守りは、作業フォルダ・承認・規則・信頼。`yolo` では確認しない（deny の規則だけが効く）。
- MCP は stdio だけ（HTTP の MCP は無い）。
- コマンドの出力は終わってからまとめて返す（途中経過は見えない）。
