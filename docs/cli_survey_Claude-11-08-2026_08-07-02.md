# 調査：ターミナルで AI を使う公開 CLI(Command Line Interface) 10 種

arce.ai-cli を作る前に、公開されているターミナル向けの AI コーディング CLI を 10 種調べ、機能を比べた結果。
**このリポジトリには、調べたツールの名前・配布元・URL などの出典を書かない**（利用者の指示。著作権などの問題を避けるため）。各ツールは「ツール A〜J」と呼ぶ。
ここに書くのは機能と設計の考え方だけで、どのツールのコード・文章・デザイン（色・ロゴ・画面の作り）も写していない。arce.ai-cli の実装は、すべて独自に書いた。

調査日：2026-11-08（日本時間）。各ツールは更新が速く、ここに書いた既定値や名前は変わりうる。

## 1. 各ツールの特徴

|---|---|---|
| A | クローズドソース。TUI(Text User Interface)。 | 権限のモード（確認・編集を自動・計画だけ・すべて許可）、ツール実行前後のフック（終了コードで止める）、読み取り専用の調査用サブエージェント、必要なときだけ本文を読み込む「スキル」、会話の自動要約、`!` でシェル直実行、`@` でファイル参照、`#` でメモリ追記、独自のスラッシュコマンド（Markdown ファイル）、非対話モード（`-p` と JSON / NDJSON(Newline Delimited JSON) の出力）、セッションの再開 |
| B | オープンソース（MIT）。TUI とサーバーが分かれる。 | 75 以上の提供元に対応、「作る（Build）」と「計画（Plan）」の 2 つの主エージェント（Plan は編集を禁止）、`@` で呼ぶサブエージェント、エージェントを Markdown のフロントマターで定義、コマンドの glob パターンごとの allow / ask / deny、LSP(Language Server Protocol) から診断を得る |
| C | オープンソース。Rust 製。 | 「サンドボックス（読み取りのみ・作業フォルダだけ書ける・全部）」と「承認の方針（信頼しないもの・必要なとき・しない）」の 2 軸、プロジェクトの設定は信頼したフォルダだけで効く、セッションを日付ごとの JSONL に保存して再開・分岐、取り消し用の影のコミット、MCP(Model Context Protocol) サーバー、git worktree による並列のエージェント、非対話の実行（JSON の出力） |
| D | オープンソース。 | 階層的な指示ファイル（全体 → プロジェクト → サブフォルダ。`@` で別ファイルを取り込む）、ファイル変更の前に影の Git リポジトリへ保存して `/restore` で戻す（会話も戻る）、拡張（MCP・スラッシュコマンド・スキルの束）、複数のサンドボックス方式、非対話モードと全自動（YOLO）フラグ |
| E | オープンソース。Python 製。 | 「リポジトリ地図」（構文木から記号を抜き出し、重要度で順位を付けてプロンプトに入れる）、編集形式の選択（差分・ファイル全体・統一差分）、設計役のモデルが案を出し編集役のモデルがファイルに直す 2 段構え、編集ごとの自動 git コミット |
| F | オープンソース。デスクトップ版と CLI が同じ実行部を共有。 | 拡張はすべて MCP サーバー、手順を YAML で書いて再利用する「レシピ」、名前・ID でのセッション再開と書き出し、提供元を自由に選ぶ |
| G | オープンソース。Go 製の TUI。 | 会話の途中でモデルを替えても文脈を保つ、プロジェクトごとの複数セッション、LSP の情報を判断に使う、プロジェクト／全体の設定ファイル、ツールは既定で確認・個別に無効化、MCP（stdio・HTTP・SSE(Server-Sent Events)） |
| H | クローズドソース（プレビュー）。 | 起動したフォルダを「信頼するか」を最初に聞く（今回だけ／以後も）、パス・URL ごとの許可（既定は作業フォルダと一時フォルダだけ、URL は毎回確認）、`--allow-tool` / `--deny-tool`、`/add-dir` で作業範囲を広げる、多数のスラッシュコマンド |

## 2. 共通して見られた設計

1. **対話（REPL(Read-Eval-Print Loop) / TUI）と非対話（1 回で終わる）の 2 つの入口**。非対話は CI(Continuous Integration) やスクリプトから使われ、出力は「最後の文だけ」「1 つの JSON」「1 行 1 イベントの JSON」の 3 種がほぼ共通。
2. **プロジェクトの指示ファイル**（Markdown）を、全体 → リポジトリの根 → 今のフォルダ の順に重ねて読む。共通の名前として `AGENTS.md` を読むツールが多い。
3. **権限は「モード」と「規則」の 2 段**。モード（確認・編集は自動・計画のみ・全部許可）で大枠を決め、規則（コマンドの前方一致や glob で allow / ask / deny）で細かく決める。deny が常に勝つ。
4. **作業範囲**：作業フォルダの外のパスは、明示的に足すか、毎回確認。
5. **リポジトリの設定は、信頼するまで効かせない**（クローンしたリポジトリの設定ファイルが、フックや送り先を書き換えられるため）。
6. **取り消し**：ファイルを書き換える前に元の内容を保存し、ターン単位で戻す。
7. **セッションの保存と再開**（JSONL など追記型のファイル。直前の会話 `--continue`、ID 指定 `--resume`）。
8. **会話の圧縮**：文脈が埋まりそうになると、古い部分を要約に置き換える。手動のコマンドもある。
9. **フック**：ツールの実行前後・入力の送信時などに外部コマンドを呼び、終了コードで止める。
10. **MCP**：外部の道具を、標準入出力か HTTP のサーバーとして足す。ツールが多いときは、定義を必要なときだけ読む工夫がある。
11. **サブエージェント / 役割の分担**：設計役と実装役、調査役（読み取り専用）など。並列に動かすツールもある。
12. **スラッシュコマンドの自作**：Markdown ファイルを置くと `/名前` で使え、`$ARGUMENTS` に引数が入る。
13. **シェルの直実行**（`!コマンド`）と、**ファイルの参照**（`@パス`）。

## 3. arce.ai-cli に採り入れたもの

| 項目 | arce.ai-cli での形 | 由来 |
|---|---|---|
| 2 つの入口 | `arce`（対話）と `arce -p "…"`（非対話。`--output-format text\|json\|stream-json`） | 共通 |
| 指示ファイル | 全体の `~/.config/arce/AGENTS.md` → リポジトリの根から今のフォルダまでの `AGENTS.md`・`ARCE.md` | 共通 |
| 権限 | モード `ask`・`auto-edit`・`plan`・`yolo` と、規則 `allow` / `ask` / `deny`（glob）。deny が最優先 | 共通 |
| 作業範囲 | 作業フォルダ＋`--add-dir`／`/add-dir`。外は確認 | 共通 |
| 信頼 | 信頼していないフォルダでは、プロジェクトの設定のうち、送り先・フック・MCP・許可の規則を読まない（`arce trust`） | 共通 |
| 取り消し | 書き換える前の内容をセッションのフォルダに保存し、`/undo` でターン単位に戻す | 共通 |
| セッション | `~/.local/share/arce/sessions/<id>.jsonl`、`-c` / `-r <id>`、`arce sessions` | 共通 |
| 圧縮 | arce.ai の方式（古い道具の結果を先に切り詰め、それでも足りなければ前半を組ごとに要約）。`/compact` | arce.ai |
| フック | `pre_tool`・`post_tool`・`prompt`・`stop`。JSON を標準入力で渡し、終了コード 2 で止める | 共通 |
| MCP | stdio のサーバー。道具が多いときは arce.ai の `mcp_find`・`mcp_describe`・`mcp_call` に切り替える | 共通＋arce.ai |
| 分担 | arce.ai のコーディングモード（プランナーが Mermaid の図で分け、複数の開発モデルが並列・依存順に実装） | arce.ai |
| 自作コマンド | `.arce/commands/*.md`・`~/.config/arce/commands/*.md`、`$ARGUMENTS` | 共通 |
| `!` と `@` | `!コマンド` でシェル、`@パス` でファイルを添付 | 共通 |

## 4. 採り入れなかったもの（今はしない）

- LSP の診断・リポジトリ地図（構文木の解析）：言語ごとの部品が大きい。必要になったら別の版で。
- OS のサンドボックス（コンテナ・seccomp など）：OS ごとの差が大きい。今は「作業範囲＋承認＋規則」で守る。
- 全画面の TUI：行ベースの REPL にした（端末の種類を選ばず、ログとしても読める）。
- 会話の共有（クラウド）：ローカルで完結させる（arce.ai の方針）。
