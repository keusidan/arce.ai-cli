# 動きの仕様

現行の仕様だけを書く。**未確認**は、実際のサービスで確かめていない。

## 返信のループ（`src/controller.rs`）
1. フック `prompt` を動かす（終了コード 2 で送信を止める。標準出力はメッセージに足す）。
2. `@パス` のファイル（テキストだけ。`limits.attach_max_chars` で切る）とフォルダの一覧を添付する。
3. エージェントを選ぶ（`agent = "auto"` ならキーワード。添付があれば File Analysis に寄せる。何も当たらなければ前の返信のエージェント）。
4. ターンを進め（取り消しの単位）、発言を保存する。
5. 繰り返し：
   - 送る前に、文脈を超えそうなら圧縮する（下）。指示と道具だけで文脈の `token_precheck.overhead_percent`% を超える、または会話が入らないときは、**送らずに**理由を出して止める（文脈の大きさが分かるモデルだけ）。
   - 送る。最初の 1 字が来るまで待ちの行を出す。失敗が**最初の 1 字より前**なら、フォールバックの規則の相手へ切り替える（下）。
   - 本文も道具も無い返信は `limits.retry_limit` 回までやり直す（思考だけで `length` に達したら、そう言って止める）。テキスト形式で道具の JSON が壊れていたら、理由を伝えて書き直させる。
   - 道具の呼び出しがあれば、1 つずつ確かめて動かし、結果を返して次へ。**同じ道具・同じ引数の組が `limits.repeat_limit` 回続いたら止める**。ラウンドは `limits.max_tool_rounds` まで。
6. フック `stop`、集計の行。

- **止める**：Ctrl-C で、その返信だけを止める（接続を切る。動いているコマンドも止める）。書けていた本文は「（ここで止められました）」を付けて残す。
- 道具の呼び出しに答えが無いまま終わった会話（途中で閉じたなど）は、開き直すときにその呼び出しから後を落とす（提供元が「答えの無い呼び出し」を断るため）。

## 道具（`src/tools.rs`）

| 道具 | 種類 | 内容 |
|---|---|---|
| `read_file` | 読む | 行番号つき。`offset`・`limit`（既定 `limits.read_default_lines`）。バイナリは断る |
| `list_dir` | 読む | フォルダの一覧（`.git` は除く） |
| `glob` | 読む | パターンでファイルを探す（`.gitignore` を守る、新しい順） |
| `grep` | 読む | 正規表現で中身を探す（`path:行: 文`、上限 `limits.grep_max_results`） |
| `write_file` | 書く | ファイル全体を書く。承認カードに色つきの差分 |
| `edit_file` | 書く | `old_string` を `new_string` に。**1 か所に決まらないと断る**（`replace_all` で全部）。見つからないときは空白の違いかどうかを言う |
| `run_command` | コマンド | `sh -c`（Windows は `cmd /C`）。標準入力は空。終了コード・stdout・stderr（長いものは頭と尻を残して切る）。`timeout_seconds`（上限 `limits.command_max_timeout_secs`） |
| `http_request` | 送信 | curl に相当。秘密は `{{secret:ID}}`（下） |
| `web_search` | — | `search.searxng_url` があれば SearXNG、無ければ DuckDuckGo の即答 API |
| `ask_user` | — | 利用者に聞く（非対話では「答えられない、いちばん妥当な選択で」と返す） |
| `update_plan` | — | チェックリストを画面に出す |
| `get_settings` / `update_settings` | 設定 | 下 |
| `delegate` | — | コーディングモード（下） |
| `mcp_<server>__<tool>`、または `mcp_find`・`mcp_describe`・`mcp_call` | MCP | 下 |

- 1 つの返信に複数の呼び出しがあれば、順に全部動かす（どれにも結果を返す。提供元が答えの無い呼び出しを断るため）。
- 道具の結果は、秘密の値を伏せてから返す（`[secret:id]`）。
- 画面とモデルに見せるパスは、作業フォルダからの相対で、区切りはどの OS でも `/`（Windows でも同じ文字列になり、モデルがそのまま書き返せる）。
- 計画モードでは、`write_file`・`edit_file`・`delegate` をモデルに渡さない。

## 権限（`src/permissions.rs`）
**モード**（`mode`、`--mode`、`/mode`）：

| モード | 読む | 書く（作業フォルダの中） | コマンド | 送信 | MCP |
|---|---|---|---|---|---|
| `ask`（既定） | 自動 | 確認 | 確認 | `permissions.http_confirm` | 確認 |
| `auto-edit` | 自動 | 自動 | 確認 | 〃 | 確認 |
| `plan` | 自動 | **禁止** | allow の規則にあるものだけ | 〃 | 確認 |
| `yolo` | 自動 | 自動 | 自動 | 自動 | 自動 |

**規則**（`permissions.allow` / `ask` / `deny`、`--allow` / `--deny`）：`道具名` か `道具名(glob)`。glob はコマンド・パス・URL のホストに当てる（例 `run_command(git status*)`、`write_file(src/**)`、`mcp_github__*`）。

決め方の順：
1. **deny** に当たれば禁止（どのモードでも）。
2. 設定の変更（`update_settings`）は、どのモードでも毎回確認。
3. 計画モードの禁止。
4. **ask** に当たれば確認。
5. 秘密を使うコマンドは確認（`yolo` 以外）。コマンドは値をどこへでも送れるため。
6. この返信で外部の内容（Web・HTTP・MCP の結果）を読んだあとのコマンドは確認（`permissions.confirm_after_external`、`yolo` 以外）。入り込んだ指示で allow の規則を使わせないため。
7. 作業フォルダ（作業フォルダ・`permissions.additional_dirs`・`--add-dir`・`/add-dir`）の外のパスは確認（`yolo` 以外）。シンボリックリンクは解決してから判断する。
8. **allow** に当たれば自動。コマンドは `&&`・`||`・`;`・`|`・改行で分けて、**全部の部分**が当たるときだけ。`$(…)`・バッククォート・リダイレクト・閉じていない引用符を含むコマンドは、allow の規則では通さない。
9. 承認カードで「この道具は以後聞かない」（`a`）を選んだ道具は自動（この実行の間だけ。**コマンドと設定の変更は覚えない**）。
10. モードの既定（上の表）。

非対話（`-p`）では、確認になるものは断り、その理由をモデルに返す（`--mode` か `--allow` で許す）。

## 信頼（`src/settings.rs`）
- 設定は `~/.config/arce/settings.toml`（利用者）に、プロジェクトの `.arce/settings.toml` を重ねる。プロジェクトは、上へたどって最初に `.arce/` か `.git` がある場所。
- **信頼していないフォルダ**では、プロジェクトの設定のうち、送り先・コマンド・権限に関わるもの（`providers`・`fallback`・`fallback_enabled`・`permissions`・`hooks`・`mcp`・`search`・`secret_hosts`・`secrets_off_for_model`）を読まず、警告を出す。クローンしたリポジトリの設定が、キーを別の場所へ送らせたり、フックでコマンドを動かしたりできないように。`arce trust` で信頼する（`trusted.json`）。
- 指示ファイル（`AGENTS.md`・`ARCE.md`）は、信頼に関係なく読む（プロンプトでは「ルールに反しない限り従う」とする）。

## 秘密（`src/secrets.rs`）
- 値は `secrets.json`（所有者だけが読める 0600）か環境変数（`ARCE_SECRET_<ID>`、プロバイダは `api_key_env` も）にだけある。**設定ファイル・会話・承認カード・ログ・エラー文には出さない**。モデルは id だけを知る（プロンプトに使える id の一覧）。
- **送ってよいホスト**：プロバイダのキーは、その `base_url` のホストが自動で入る。ほかの秘密は `arce secrets set <id> --host …` か `secret_hosts`。`*.example.com` は配下だけ（`example.com` 自身は含まない）。
- `http_request`：`{{secret:ID}}` は URL のホストより後ろ・ヘッダの値・本文だけ。差し込んだあとの URL が、使う秘密すべてのホストに入っていて、https（設定でオンにしたときだけ http）で、ユーザー名つきでなく、ホストに `%` が無く、**この端末や内側のネットワーク（localhost・私的アドレス・`.local` など・数字だけのホストの変わった書き方）でない**ことを確かめ、どれかが駄目なら何も送らない。リダイレクトは、秘密を使うときは同じホストの https にだけ（回数は `permissions.http_max_redirects`）。
- `run_command`：`{{secret:ID}}` をコマンドに差し込むか、`secrets: ["id"]` で環境変数 `ARCE_SECRET_<ID>` に入れる。**送り先は制限できない**ので、`yolo` 以外では毎回確認。
- **伏せ字**：道具の結果すべてから、値そのもの・URL エンコード（2 通り）・JSON のエスケープ・`\uXXXX`・HTML 実体・hex・base64（2 種類のアルファベット、padding の有無、長い base64 の中の 3 つの位置）を `[secret:id]` に置き換える。4 文字未満の値は伏せない。
- `secrets_off_for_model` に入れた id は、モデルに使わせない（伏せ字の対象には残る）。

## セッションと取り消し（`src/session.rs`）
- `~/.local/share/arce/sessions/<id>.jsonl` に追記する（メタ・発言・圧縮後の履歴の置き換え・題・ターン）。`-c` はこのフォルダの最新、`-r <id>` は指定、`--no-session` は保存しない。
- 道具がファイルを変える**前に**、そのターンで初めて触るファイルの中身を `sessions/<id>/checkpoints/<ターン>/` に控える（無かったファイルは「無かった」と記録）。`/undo` は最新のターンのファイルを戻し（新しく作ったファイルは消す）、モデルに「戻した」と伝える。会話は消さない。
- 検索（`/sessions 語`、`arce sessions search`）は、題と本文に、空白で区切った語がすべて入っているもの（大文字小文字を区別しない）。

## 会話の圧縮（`src/compaction.rs`）
`arce_heritage` の表のとおり（アプリと同じ）。文脈の大きさ（モデルの `context_tokens`）が分かるときだけ自動。`/compact` はいつでも。要約は、いま使っているモデルが、思考をオフにして書く。

## コーディングモード（`src/delegation.rs`）
- 条件：`coding.enabled`・開発モデル（`coding.developers`）が 1 つ以上・プランナーが決まっている（既定は使用中のモデル。`coding.planner_follows_model = false` なら `coding.planner`）。Coding エージェントのときだけ、プランナーに `delegate` と指示を渡す。
- 流れは `arce_heritage` の表のとおり。CLI では、開発モデルが `File: パス` のあとのコードブロックで書いたファイルを、**1 枚の承認カードでまとめて**作業フォルダに書く（`coding.apply_files`。deny の規則・計画モードは個別に効く。書く前に控えを作るので `/undo` で戻せる）。プランナーには「書いたファイル」と、番号つきの結果（`coding.result_chars` で切る）を返す。
- 同時に走る数は、開発モデルごとに `coding.parallel`。開発モデルの温度は `coding.developer_temperature`（モデルの設定が先）。

## MCP（`src/mcp.rs`）
- `[[mcp.servers]]`（`id`・`command`・`args`・`env`・`enabled`・`trusted_tools`）。stdio で JSON-RPC（1 行に 1 つ）。`initialize` → `notifications/initialized` → `tools/list`（`nextCursor` で続き）→ `tools/call`。`env` の値に `{{secret:ID}}` を書ける（起動のときに差し込む）。
- 道具の合計が `mcp.lazy_threshold`（既定 40）を超えると、モデルには `mcp_find`・`mcp_describe`・`mcp_call` だけを渡す。
- MCP の結果は「外部の内容」として扱う（そのあとのコマンドは確認）。`trusted_tools` の道具は確認しない。

## フック（`src/hooks.rs`）
`[[hooks]]`（`event`・`matcher`（道具名の glob、空なら全部）・`command`）。標準入力に JSON（`event`・`tool`・`input`・`output`・`session_id`・`cwd`）、環境変数 `ARCE_HOOK_EVENT`・`ARCE_HOOK_TOOL`。

| event | いつ | 終了コード 2 |
|---|---|---|
| `prompt` | メッセージを送る前 | 送信を止める（標準出力はメッセージに足す） |
| `pre_tool` | 道具を動かす前（承認のあと） | その呼び出しを断り、標準エラーをモデルに伝える |
| `post_tool` | 道具のあと | 標準エラーを結果に足す |
| `stop` | 返信の終わり | — |

0 と 2 以外の終了コード・時間切れ（`limits.hook_timeout_secs`）は、警告を出して続ける。

## 出力の形（`-p`）
- `text`：答えの本文だけを標準出力に（端末でなければ Markdown の飾りも無し）。思考・道具・注意・集計は標準エラーに。
- `json`：終わりに 1 行 `{"type":"result","status":"done|failed|cancelled","error","result","session_id","model","requests","tools","duration_ms","usage"?,"events":[…]}`。
- `stream-json`：1 行 1 イベント（`text`・`reasoning`・`reasoning_end`・`tool_call`・`tool_result`・`notice`・`plan`・`shown`・`approval_refused`・`question_unanswered`・`reply_end`）、最後に `result`。
- 終了コード：0 完了、1 失敗、130 中断。`-p` は標準入力も読む（引数のあとに足す）。

## プロンプト（`src/prompt.rs`）
基本の規則 → 環境（作業フォルダ・OS・git か）→ 役割（エージェント）→ モード → 使える秘密の id → MCP の案内 → コーディングモードの指示 → 指示ファイル（全体の `~/.config/arce/AGENTS.md`、プロジェクトの根から今のフォルダまでの `AGENTS.md`・`ARCE.md`、外側から順）→ 利用者の追加の指示 → 口調（`<tone>`、制御文字と `<` `>` を除いて 200 字まで）。**時刻・回数など毎回変わるものは入れない**。
